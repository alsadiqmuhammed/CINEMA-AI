# المعمارية وخطة التنفيذ

## المبدأ التشغيلي

> الأتمتة تسوي الأعمال المتكررة وتجهّز المسودات وتتابع العملاء. والإنسان يراجع القرارات الحساسة.

هذا المبدأ مطبّق في الكود نفسه، مو بس مكتوب:

- **المساعد الذكي والأتمتة ما عندهم حساب موظف.** يشتغلون عن طريق أدوات محددة، وكل قرار حساس يتحول لـ**طلب موافقة** في جدول `approvals`.
- **الصلاحيات منفصلة:** الموظف يدير المنتجات والطلبات والعملاء والمحادثات. المدير يضيف عليها الموافقات والمدفوعات. والمالك يقدر يسوي كل شيء.
- **كل إجراء ينسجل في `audit_log`:** وش انعمل، ومنو سوّاه (مستخدم أو `ai` أو `automation` أو `customer`)، ومتى، وعلى أي عنصر، وليش.

## الربط بين الأجزاء

```text
                 ┌──────────────┐     ┌──────────────────┐
  الزوار  ──────▶│  واجهة المتجر │────▶│  السلة والطلبات   │──┐
                 └──────┬───────┘     └──────────────────┘  │
                        │ أداة المحادثة                       │
  واتساب  ──Webhook──▶ ┌▼──────────────┐  أدوات محددة          ▼
  (Meta)               │ مساعد المحادثة │────────────▶ ┌──────────────┐
                       │   (Claude)    │  بحث، طلب،    │  PostgreSQL  │
                       └──────┬────────┘  تصنيف، تحويل │  (CRM مركزي)  │
                              │ حالة حساسة              └──────▲───────┘
                              ▼                                │
                       ┌──────────────┐     ┌──────────────┐   │
                       │ صندوق المحادثات│     │   الأتمتة     │───┤
                       │   (موظف)      │     │ (كل 5 دقائق)  │   │
                       └──────────────┘     └──────┬───────┘   │
                                                   ▼           │
  ┌───────────────┐   موافقة   ┌──────────────┐  ┌──────────┐  │
  │ مسودات المحتوى  │──────────▶│  الموافقات    │  │ الرسائل   │──┘
  │ والحملات (AI)  │           │ (مدير/مالك)   │─▶│ الصادرة   │──▶ واتساب
  └───────────────┘           └──────────────┘  └──────────┘
```

**ليش بنية وحدة مو مجموعة أدوات متفرقة؟** المتجر والـ CRM والمحادثات والأتمتة كلها تقرا وتكتب في نفس قاعدة البيانات. فالعميل اللي يكلّمك على واتساب هو نفس العميل اللي طلب من الموقع، وطلبه ومحادثته بنفس الملف. وما فيه مزامنة بين أنظمة ممكن تفشل.

## وش ينأتمت فوراً ووش يحتاج موافقة

| الإجراء | ينفذه | ملاحظات |
|---|---|---|
| الرد على أسئلة المنتجات والسياسات | المساعد تلقائياً | من الكتالوج والسياسات بس، وممنوع عليه يخترع |
| اقتراح منتجات مكملة أو بديلة | تلقائي | العلاقات يحددها الفريق، وإذا ما فيه علاقات يقترح من نفس التصنيف |
| إنشاء رابط طلب | المساعد تلقائياً | الدفع وإدخال العنوان يصيرون في صفحة المتجر، والمساعد ما يطلب بيانات بطاقة أبداً |
| حفظ بيانات العميل وتصنيف المحادثة | المساعد تلقائياً | |
| تذكير السلة المتروكة وطلب التقييم | الأتمتة تلقائياً | مرة وحدة لكل سلة أو طلب، وبقالب معتمد خارج نافذة الـ 24 ساعة |
| تنبيهات المخزون والتأخير والشكاوى والدفع | الأتمتة تلقائياً | |
| تحويل الاسترجاع والشكاوى ومشاكل الدفع لموظف | المساعد تلقائياً | والمساعد يوقف رده على المحادثة بعدها |
| نشر محتوى منتج كتبه المساعد | **يحتاج موافقة** مدير أو مالك | |
| تأكيد استلام مبلغ | **موظف بصلاحية مدفوعات** | |
| استرجاع مبلغ | **يحتاج طلب ثم موافقة** | التحويل الفعلي للعميل يصير يدوياً |
| رسالة جماعية تسويقية | **يحتاج موافقة** | تروح بس للموافقين على التسويق |
| خطة حملة إعلانية | **يحتاج موافقة** | الإطلاق وصرف الميزانية يدوياً من Meta |

## المراحل

### المرحلة 1: الأساس (هذا الإصدار)
- المتجر العربي، والسلة، والدفع عند الاستلام والتحويل البنكي، وتتبع الطلب، والـ SEO.
- لوحة التحكم، والـ CRM، والصلاحيات، وسجل التدقيق، والتنبيهات.
- مساعد المحادثة على الموقع وواتساب، مع التحويل لموظف.
- الأتمتة: السلال المتروكة، وطلب التقييم، والتنبيهات.
- مسودات المحتوى واقتراح الحملات ضمن مسار الموافقات.

### المرحلة 2: الدفع الإلكتروني وقنوات Meta
- بوابة دفع إلكتروني حسب الدولة (مثل Moyasar أو Tap أو MyFatoorah أو Stripe)، تأكيد الدفع فيها يصير بـ Webhook موقّع، ويتسجل في سجل التدقيق. الحقل `payment_method = 'online'` جاهز بقاعدة البيانات.
- محوّلات ماسنجر وانستقرام بنفس واجهة قناة واتساب (`src/channels/`).
- تخزين الصور على S3 أو R2، وإرسال الإيميلات.
- واجهة إنجليزية (النصوص حالياً في ملفات العرض، وراح تنتقل لملفات ترجمة).

### المرحلة 3: التسويق
- خطة محتوى شهرية ومنشورات من قوالب الهوية، وجدولة النشر عبر Meta Graph API بعد الموافقة.
- ربط Meta Marketing API لإنشاء الحملات كـ **مسودات متوقفة (paused)**، وما تشتغل إلا بموافقة صريحة.
- قياس أداء المحتوى والإعلانات في لوحة الأداء.

### المرحلة 4: التوسّع
- نقل المهام الدورية لطابور مستقل، ونسخ متعددة من الخادم. الأتمتة تستخدم قفل PostgreSQL من الحين، فتقدر تشتغل على أكثر من نسخة.
- تقارير متقدمة وتقسيم سلوكي أعمق للعملاء.

## المخاطر والقيود

| الخطر | التعامل معه |
|---|---|
| **سياسات واتساب:** خارج 24 ساعة من آخر رسالة للعميل ما يُسمح إلا بقوالب معتمدة، والرسائل التسويقية تحتاج موافقة العميل | النظام يختار القالب تلقائياً خارج النافذة، والرسائل الجماعية تقتصر على `marketing_opt_in`. والرقم معرّض للتقييد إذا كثرت البلاغات، فلازم تكون الرسائل قليلة ومفيدة |
| **سياسات Meta للإعلانات** (المنتجات المقيدة والنصوص الممنوعة) | الحملات عبارة عن اقتراحات، والإنسان يراجعها ويطلقها |
| **أخطاء الذكاء الاصطناعي** | المساعد مقيد بأدوات تقرا من قاعدة البيانات، وما يعطي أسعار من عنده. والمحتوى ما ينشر بدون موافقة. وإذا رفض النموذج أو صار خطأ في الخدمة، تتحول المحادثة لموظف |
| **المدفوعات** | تأكيد الدفع والاسترجاع قرارات بشرية بصلاحية منفصلة. والدفع الإلكتروني (المرحلة 2) يعتمد على Webhooks موقّعة من البوابة، مو على صفحة الرجوع |
| **حماية البيانات** (مثل نظام حماية البيانات الشخصية PDPL) | أقل قدر ممكن من البيانات، وسياسة خصوصية واضحة، وصلاحيات منفصلة، وكلمات مرور مشفرة بـ scrypt، وجلسات HttpOnly. وبيانات المحادثة تنرسل لـ Anthropic للمعالجة، وهذا لازم يتذكر في سياسة الخصوصية |
| **فشل تكامل** (واتساب أو Claude) | الرسائل تبقى في `outbox` وتنعاد المحاولة 3 مرات، وبعدها يطلع تنبيه. وإذا تعطل Claude تتحول المحادثات لموظف، والمتجر نفسه ما يتأثر |
| **النسخ الاحتياطي** | النسخ الاحتياطي اليومي لـ PostgreSQL من مزود الاستضافة (Neon أو Supabase أو RDS)، ونسخ مجلد الصور أو نقله لـ S3 بالمرحلة 2 |

## التشغيل والصيانة
- `GET /healthz` يبين حالة قاعدة البيانات والتكاملات.
- الجداول تتحدث تلقائياً عند التشغيل (`src/db/migrations`). أي تعديل يكون بملف جديد مرقّم، وما نعدل على الملفات القديمة.
- `npm run worker` يشغّل دورة أتمتة وحدة يدوياً، وينفع للاختبار أو للتشغيل بجدولة خارجية.
